# Tasks conventions

**One folder per substantial finite pursuit or decision frame** at
`about/tasks/<slug>/`, entered through `intro`.

A task here is an outcome, experiment or consequential decision the owner is actively
thinking through and which can resolve or close. It is not a to-do item: if it can be
finished in an afternoon, it does not get a folder. Nor is it the durable home of a
long-lived body of work; that belongs under [[about/projects/agents|projects]].

## Minimal shape

    about/tasks/<slug>/
    ├── intro       — what the effort is and why it matters
    └── timeline    — its dated history, when it has one

`intro` is the only page this default guide requires. Add another page or nested folder
only when its contents are worth reading, retrieving or linking on their own. Name it
for what it actually contains.

Beyond `intro` and `timeline`, there are no default names or prescribed supporting pages
for a task. If an instance develops a recurring structure, record that vocabulary in its
copy of this guide. If a single task needs conventions that do not belong to every task,
give that task folder its own local `agents` guide.

**A task usually contains other entities**, and they follow
[[agents#entities-are-folders-and-views-are-pages|the root rule]]: anything the task
accumulates that could be described without the task — an application, a period being
accounted for, an option under evaluation — is a folder of its own inside the task, not
a flat page. Pages hold the task's own thinking: the frame, the reasoning and the
comparisons that only mean something here.

## The line this directory has to hold

**A task page says what the effort is and how the owner is thinking about it. It never
carries a status field.** No "waiting on", no next step, no undated progress note, no
`Updates` section ([[agents#durable-pages-and-the-diary|root rule]]).

Where it stands is answered two ways, neither of them a field: the recent diary says
what the owner has been doing, and a `timeline` — on the task, or on the entity inside it
that actually moved — carries one dated line per state the thing has passed through,
linking the diary entry or meeting that holds the work. The current state is the most
recent line.

Put the dated line on the smallest entity it is true of. An application's history belongs
to that application, not to the effort containing it; the task's own timeline carries
only what changed the effort as a whole.

That is what makes these pages worth keeping. A task folder that tracked progress in
prose would need rewriting every week and would be wrong in between; one that holds the
durable frame, with history dated beside it, stays true on its own.

Observed activity does not create a task by itself. Record what happened in the diary;
create a task only when the evidence establishes a real future-facing pursuit or
decision frame useful beyond that day.

**Judgement about an entity is not part of the task either.** Whether a company is worth
joining or a person is worth partnering with belongs on a lens page in that entity's
folder ([[companies/agents|companies]], [[people/agents|people]]). The task links to it
instead of explaining the entity again.

## Closing a task

When a task resolves, give the outcome its durable home — often the related
[[about/projects/agents|project]], but whichever page owns the resulting truth. The task
folder stays as the reasoning record, its timeline ends with the dated resolution, and
the diary holds how it unfolded. Do not rewrite the task into a retrospective.

## Local rules

- **Write in the owner's first person, from what they have actually said**, and mark
  added reasoning as inference. Never quietly upgrade a suggestion into their position.
- **Create structure only for real material.** Do not create empty placeholder pages to
  make two task folders look alike, and do not open a timeline before something has
  happened.
- **Link instead of restating.** People, companies, meetings, events and durable topics
  keep their own canonical pages; task pages contain only the effort-specific thinking.
