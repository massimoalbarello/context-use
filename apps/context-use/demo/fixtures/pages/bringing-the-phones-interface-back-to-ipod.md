# Bringing the phone’s interface back to iPod

[I](context-use://entity/steve-jobs) am bringing the [phone's touch interaction](context-use://page/building-a-phone-around-our-fingers) back into [iPod touch](context-use://entity/ipod-touch). The [September launch thread](context-use://record/touch-launch) closes a loop that started with the [original player](context-use://page/putting-the-first-ipod-in-my-pocket) and changed direction after [ROKR](context-use://page/comparing-nano-and-rokr-with-tony).

[Tony](context-use://entity/tony-fadell) owns the player execution. [Phil](context-use://entity/phil-schiller) must explain the boundary: touch has Wi-Fi, Safari and the Wi-Fi Music Store, without cellular phone service. The 8GB/$299 and 16GB/$399 models are scheduled for later this month.

I asked [Scott](context-use://entity/scott-forstall) to consider touch in the application work. The [July developer feedback](context-use://record/developer-feedback) is now relevant to two products. Reusing an interface also creates expectations we need to own together.
