# How I connect hardware and software

[I](context-use://entity/steve-jobs) keep returning to a person's complete task: acquire something, organize it, carry it and use it. The [first iPod rehearsal](context-use://record/demo-handoff) is the earliest concrete test in these notes. A prepared device hides the work; starting with the library exposes it.

The principle has changed my decisions. I accepted [Musicmatch](context-use://page/opening-ipod-to-windows-customers) to reach PC owners, then [owned Windows iTunes](context-use://page/bringing-our-own-itunes-to-windows) to close the gap. The [ROKR review](context-use://page/comparing-nano-and-rokr-with-tony) exposed the same issue across handset and carrier, pushing the phone work toward a complete interaction.

It is not a rule to own everything. [Shuffle](context-use://page/choosing-a-simpler-player-with-shuffle) moves work to AutoFill; the [Disney agreement](context-use://page/working-with-bob-to-put-television-in-itunes) supplies content; the [SDK decision](context-use://page/committing-to-native-applications-for-iphone) opens useful work to other developers. My question is who can resolve the failure when the person's task crosses a boundary.

For my next review, ask someone to perform the task from an ordinary starting point. If we need to explain away a seam, that is evidence to bring back into the design.
